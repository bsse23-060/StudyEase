# Deployment

Local production-like startup is `docker compose up --build --wait`, followed by `docker compose exec api python manage.py seed_demo` and `pwsh scripts/smoke_test.ps1`. The default uses fake AI/scanner providers and a private local volume. Add `--profile s3 --profile scanner` to start optional MinIO and ClamAV, then point the API/worker storage and scanner variables at them. The production override requires external secrets and enables ClamAV. Create a private versioned bucket before production startup.

Production sequence: build immutable SHA-tagged images; test and scan; push to the approved registry; verify backup/restore point; run backward-compatible migrations once; roll API and workers with surge capacity; deploy frontend; require readiness and authenticated smoke checks; then shift traffic. Keep the previous images and database compatibility through the rollback window. A failed migration stops rollout—do not blindly reverse data migrations. Roll back application images first, restore a database only when forward repair is unsafe, and document data loss against RPO.

TLS belongs at a managed edge/publicly trusted reverse proxy. The example Nginx listens on HTTP 8080 for local/private use and is not a certificate solution. Configure DNS, certificate renewal, firewall, secret manager, managed backups, alerts, worker autoscaling, and network policies for the selected provider. Recommended first staging target: Render or Railway for simplicity, or AWS ECS/RDS/ElastiCache/S3 when stronger network/operations control is required; obtain cost approval first.
