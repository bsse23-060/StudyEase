# Incident response

For credential leaks, malicious uploads, unauthorised access, data exposure, queue abuse, provider compromise, database loss, or outage: declare an incident, preserve timestamps/request IDs and append-only evidence, limit access, contain without destroying evidence, rotate affected credentials, notify the accountable owner, eradicate, restore from verified state, validate authorization/smoke checks, and document decisions. Do not automatically download quarantined files.

Credential leak: revoke at provider, rotate, invalidate sessions, search safe audit metadata. Malicious upload: isolate object and worker, update signatures, find checksum matches. Data exposure/unauthorised access: block actor/path, preserve proxy/audit logs, assess exact records and notification obligations. Queue abuse: pause producers, revoke actor, discard only verified stale tasks. Provider compromise: disable integration/key and switch to fake/offline mode. Database loss: freeze writes and follow PITR. Conduct a blameless review with root cause, scope, timeline, remediation owner, and verification evidence; vendor contacts and legal notification trees must live in the private incident system, not this repository.
