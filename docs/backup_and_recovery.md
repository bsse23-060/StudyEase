# Backup and recovery

Target starting objectives are RPO 15 minutes and RTO 4 hours; a provider/SLA review must confirm them. PostgreSQL needs encrypted daily logical backups plus provider PITR/WAL, retained 35 days (monthly snapshots for 12 months if policy approves). Private object storage needs encryption, versioning, deletion protection, and matching retention. Back up database and objects consistently enough that object checksums can be reconciled. Redis, embeddings, HNSW indexes, OpenAPI output, and frontend builds are regenerable; user/course records, educational history, conversations/citations, audit records, documents, and storage metadata are not.

Use `scripts/backup_postgres.ps1`, then `scripts/restore_postgres.ps1 -Input ...` to restore into an isolated database. A dump is not verified until restore, migration checks, row/checksum sampling, authorization smoke tests, and application readiness pass. Test restores quarterly. Rotate and access-log backup keys. For recovery: freeze writes, select PITR point, restore DB and object versions, run integrity checks, rebuild vectors/indexes if needed, smoke test privately, then reopen traffic.

The 2026-07-21 drill created a 175,404-byte custom dump and restored it into `studyease_restore_213838`. Restore completed in approximately three seconds; 46 migrations, pgvector 0.8.5, users, courses, documents and chunks were verified. A separate Gunicorn process started against the restored database, Django checks and migration state passed, restored login/profile/course/enrolment/attempt/conversation requests returned 200, pgvector retrieval returned the expected restored document chunk, existing citation relationships were valid, and an isolated write was created and removed. Uploaded objects are not in the PostgreSQL dump; use the separately tested object workflow in `docs/object_storage_backup_and_recovery.md`.
